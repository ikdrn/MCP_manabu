# 01 - MCP 概要とアーキテクチャ

## MCPとは何か

**MCP（Model Context Protocol）** は、LLM（大規模言語モデル）アプリケーションと外部のデータソースやツールを標準化された方法で接続するための **オープンプロトコル** です。

2024年11月に Anthropic が発表し、その後 OpenAI、Google、Microsoft なども採用。2025年12月には Linux Foundation 傘下の **Agentic AI Foundation** に寄贈され、業界標準となりました。

### 一言で言うと

> MCPは「AIアプリケーションのためのUSB-C」です。
> どんなAIアプリでも、どんな外部サービスでも、統一された規格で接続できます。

## なぜMCPが必要なのか

### MCPが無い世界の問題

```
┌─────────────┐     独自API      ┌──────────────┐
│  AI App A    │ ←──────────────→ │  サービス X   │
│              │     独自API      │              │
│              │ ←──────────────→ │  サービス Y   │
└─────────────┘                  └──────────────┘

┌─────────────┐     別の独自API   ┌──────────────┐
│  AI App B    │ ←──────────────→ │  サービス X   │
│              │     別の独自API   │              │
│              │ ←──────────────→ │  サービス Y   │
└─────────────┘                  └──────────────┘
```

**問題点:**
- AIアプリごとに個別の統合コードが必要（M x N 問題）
- サービス側も各AIアプリ向けにアダプタを用意する必要がある
- コンテキストの受け渡し方法がバラバラ

### MCPがある世界

```
┌─────────────┐                  ┌──────────────┐
│  AI App A    │ ←── MCP ──────→ │  MCP Server X │
└─────────────┘        ↑         └──────────────┘
                       │
┌─────────────┐        │         ┌──────────────┐
│  AI App B    │ ←── MCP ──────→ │  MCP Server Y │
└─────────────┘                  └──────────────┘
```

**解決:**
- 統一プロトコルで M + N の統合で済む
- 一度MCPサーバーを作れば、どのAIアプリからも利用可能
- 一度MCPクライアントを作れば、どのMCPサーバーにも接続可能

## アーキテクチャの全体像

MCPは **3つの主要な役割** で構成されます。

```
┌─────────────────────────────────────────────────────────────┐
│                        Host（ホスト）                        │
│  Claude Desktop / Cursor / VS Code / 独自アプリ など        │
│                                                             │
│  ┌─────────────────┐  ┌─────────────────┐                  │
│  │  MCP Client A   │  │  MCP Client B   │  ...             │
│  │  （クライアント）  │  │  （クライアント）  │                  │
│  └────────┬────────┘  └────────┬────────┘                  │
│           │                    │                            │
└───────────┼────────────────────┼────────────────────────────┘
            │  JSON-RPC 2.0      │  JSON-RPC 2.0
            │  (stdio / HTTP)    │  (stdio / HTTP)
            │                    │
   ┌────────▼────────┐ ┌────────▼────────┐
   │  MCP Server A   │ │  MCP Server B   │
   │  （サーバー）     │ │  （サーバー）     │
   │                 │ │                 │
   │  ┌───────────┐  │ │  ┌───────────┐  │
   │  │ Tools     │  │ │  │ Resources │  │
   │  │ Resources │  │ │  │ Prompts   │  │
   │  │ Prompts   │  │ │  │ Tools     │  │
   │  └───────────┘  │ │  └───────────┘  │
   └─────────────────┘ └─────────────────┘
```

### 1. Host（ホスト）

ユーザーが直接操作するアプリケーションです。

- **役割:** MCPクライアントを内部に持ち、ユーザーとLLMの仲介をする
- **例:** Claude Desktop、Cursor、Windsurf、VS Code、カスタムアプリ
- **責務:**
  - ユーザーの同意管理（ツール実行の承認など）
  - MCPクライアントのライフサイクル管理
  - セキュリティポリシーの適用

### 2. Client（クライアント）

プロトコルの「クライアント側」を担当するコンポーネントです。

- **役割:** MCPサーバーとの1対1の接続を維持する
- **責務:**
  - サーバーとのJSON-RPC通信
  - ケーパビリティのネゴシエーション
  - メッセージのルーティング

### 3. Server（サーバー）

外部の機能やデータを公開するコンポーネントです。

- **役割:** 特定の機能をMCPプロトコル経由で提供する
- **公開する3つのプリミティブ:**

| プリミティブ | 説明 | 制御主体 | HTTPの類似概念 |
|------------|------|---------|--------------|
| **Tools** | アクションを実行する | モデル（LLM） | POST エンドポイント |
| **Resources** | データを読み取る | アプリケーション | GET エンドポイント |
| **Prompts** | テンプレートを提供する | ユーザー | なし（UI的な概念） |

## LSP との類似性

MCPは **LSP（Language Server Protocol）** から着想を得ています。

| 項目 | LSP | MCP |
|-----|-----|-----|
| 目的 | エディタと言語サーバーの接続 | AIアプリと外部ツール/データの接続 |
| 通信 | JSON-RPC | JSON-RPC 2.0 |
| 関係 | エディタ ↔ 言語サーバー | AIホスト ↔ MCPサーバー |
| 解決する問題 | M x N → M + N | M x N → M + N |

LSPのおかげで、VSCodeやNeovimなど **どんなエディタでも** TypeScript、Python、Rustなどの **どんな言語でも** コード補完やエラー表示ができるようになりました。MCPは同じアプローチをAIの世界に持ち込んでいます。

## 通信の流れ（概念図）

```
User          Host/Client         MCP Server
  │                │                   │
  │  質問を入力     │                   │
  │──────────────→│                   │
  │                │  initialize       │
  │                │──────────────────→│
  │                │  initialized      │
  │                │←──────────────────│
  │                │                   │
  │                │  tools/list       │
  │                │──────────────────→│
  │                │  ツール一覧返却    │
  │                │←──────────────────│
  │                │                   │
  │                │ （LLMがツール選択） │
  │                │                   │
  │                │  tools/call       │
  │                │──────────────────→│
  │                │  実行結果返却      │
  │                │←──────────────────│
  │                │                   │
  │  回答を表示     │                   │
  │←──────────────│                   │
```

## 具体的なユースケース

### 1. 開発ツール統合
- Git操作（コミット、ブランチ管理）
- データベースクエリの実行
- CI/CDパイプラインの制御

### 2. データアクセス
- ファイルシステムの読み書き
- Google Drive / Slack / Notion などのSaaS連携
- 社内ナレッジベースの検索

### 3. 外部API連携
- 天気情報の取得
- 株価データの参照
- 地図サービスとの連携

### 4. エンタープライズ
- 社内システムへの安全なアクセス
- 顧客データの検索（権限制御付き）
- ワークフローの自動化

## 採用状況（2025-2026年）

- **2024年11月:** Anthropic が MCP を発表
- **2025年3月:** OpenAI が正式採用
- **2025年中:** Google、Microsoft も対応を開始
- **2025年12月:** Linux Foundation の Agentic AI Foundation に寄贈
  - 月間 9,700万 SDK ダウンロード
  - 10,000以上のアクティブ MCPサーバー
  - 数百のAIクライアントが統合
